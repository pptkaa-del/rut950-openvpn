1. Как это работает

Роутер на мобильном интернете почти всегда получает «серый» IP-адрес от оператора: подключиться к нему из интернета напрямую нельзя. Поэтому используется промежуточный сервер (VPS) с белым IP:

  1. На VPS работает OpenVPN-сервер.
  2. RUT950 сам подключается к серверу как VPN-клиент и сообщает серверу свою локальную подсеть (например 192.168.50.0/24).
  3. Ваш компьютер тоже подключается к серверу и автоматически получает маршрут до этой подсети.
  4. Вы обращаетесь к устройству за роутером по его локальному IP — как будто находитесь рядом.

Технически: на сервере для роутера создаётся файл ccd/<имя> с директивой iroute, в конфиг сервера добавляются route и push "route …", а client-to-client позволяет клиентам видеть друг друга. Всё это делает скрипт автоматически.

1Аренда и подготовка VPS

  1. Арендуйте VPS с Ubuntu 22.04+ или Debian 11+. Запишите IP-адрес и пароль root (или SSH-ключ).
  2. Если у хостера есть облачный firewall / группы безопасности — разрешите входящий трафик на UDP 1194 (и TCP 22 для SSH).
  3. Подключитесь к серверу с компьютера (PowerShell / Терминал):
ssh root@203.0.113.10
  1. Обновите систему и установите git:
apt update && apt upgrade -y
apt install -y git

2Установка OpenVPN-сервера

2.1. Скачайте проект

git clone https://github.com/pptkaa-del/rut950-openvpn.git
cd rut950-openvpn
chmod +x openvpn-rut.sh
Без gitМожно скопировать файл с компьютера: scp openvpn-rut.sh root@203.0.113.10:/root/, затем на сервере chmod +x /root/openvpn-rut.sh.

2.2. Запустите установку

sudo ./openvpn-rut.sh install

Скрипт установит OpenVPN и Easy-RSA, создаст центр сертификации и ключи сервера, определит внешний IP, включит IP-форвардинг, откроет порт и запустит службу openvpn-server@server с автозапуском.

Дополнительные параметры (необязательно):

ПараметрПо умолчаниюКогда менять
--port1194Если порт занят или блокируется — например 443.
--protoudptcp — если мобильный оператор режет UDP (медленнее, но надёжнее).
--endpointавтоЕсли у сервера есть домен (vpn.example.com) или IP определился неверно.
--vpn-net10.8.0.0Если 10.8.0.0/24 уже используется в ваших сетях.
# пример: TCP на порту 443 с доменом
sudo ./openvpn-rut.sh install --proto tcp --port 443 --endpoint vpn.example.com

2.3. Если на сервере уже работает WireGuard (или другой VPN)

OpenVPN и WireGuard спокойно работают на одном сервере: у них разные интерфейсы (tun0 и wg0) и разные порты (1194/UDP и 51820/UDP). Проверьте три вещи:

ЧтоРиск и решение
VPN-подсетьГлавная ловушка: wg-easy и многие инструкции по WireGuard используют 10.8.0.0/24 — ту же подсеть, что и OpenVPN по умолчанию. Скрипт это проверит и остановится. Устанавливайте с другой подсетью: install --vpn-net 10.9.0.0. Посмотреть занятые подсети: ip -4 route.
ПортКонфликт только если WireGuard слушает 1194 (обычно 51820). Скрипт проверит порт; при необходимости укажите --port 1195.
FirewallСкрипт добавляет свои правила iptables для tun+ и не трогает правила WireGuard (wg0, PostUp/PostDown, Docker у wg-easy). При активном ufw он откроет порт OpenVPN и разрешит форвардинг.

Если нужен доступ к LAN роутера и из WireGuard-клиентов, добавьте в WireGuard-клиенте в AllowedIPs подсеть 192.168.50.0/24, а на сервере разрешите форвардинг между интерфейсами: iptables -I FORWARD -i wg0 -o tun0 -j ACCEPT.

Ожидаемый результат[+] Готово! OpenVPN-сервер запущен. Проверка: systemctl status openvpn-server@server — статус active (running).

3Подготовка RUT950

3.1. Обновите прошивку

Веб-интерфейс роутера → System → Firmware → обновите до последней версии RutOS. Новые прошивки содержат более свежий OpenVPN и удобную загрузку .ovpn-файлов.

3.2. Смените LAN-подсеть роутера

Это важно!По умолчанию у RUT950 подсеть 192.168.1.0/24 — такая же, как у большинства домашних и офисных роутеров. Если ваш компьютер находится в такой же подсети, трафик к устройству пойдёт в вашу локальную сеть, а не в VPN, и доступа не будет.
  1. Network → LAN (на старых прошивках Network → Interfaces → LAN → Edit).
  2. IP address: 192.168.50.1, Netmask: 255.255.255.0.
  3. Проверьте диапазон DHCP — он должен быть в той же подсети (например 192.168.50.100–249).
  4. Save & Apply. Переподключитесь к роутеру по новому адресу https://192.168.50.1.

3.3. Проверьте устройство

  • Узнайте IP устройства: Status → Network → LAN (список DHCP-клиентов). Лучше закрепить за ним статический адрес (Static Leases).
  • У устройства шлюз по умолчанию должен быть 192.168.50.1 (при DHCP от роутера — так и есть).

4Создание сертификата для роутера

На сервере укажите имя роутера (латиница, цифры, -, _) и его LAN-подсеть:

sudo ./openvpn-rut.sh add-router rut950 192.168.50.0/24

Будет создана папка /root/openvpn-clients/rut950/ и архив /root/openvpn-clients/rut950.tar.gz:

5Перенос файлов на компьютер

На компьютере в PowerShell:

scp root@203.0.113.10:/root/openvpn-clients/rut950.tar.gz .
tar -xzf rut950.tar.gz

Появится папка rut950 с файлами. Альтернатива — программа WinSCP: подключитесь к серверу по SFTP и скачайте папку /root/openvpn-clients/rut950.

7Firewall на RUT950

RutOS помещает OpenVPN-интерфейс в отдельную зону firewall (обычно vpn или openvpn). Нужно разрешить трафик из VPN в LAN.

  1. Network → Firewall → General Settings (на RutOS 7: Network → Firewall → Zones).
  2. У зоны vpn/openvpn: Input = Accept, Output = Accept, Forward = Accept.
  3. В настройках зоны (Edit) → Allow forward to destination zones: отметьте lan.
  4. У зоны lan → Allow forward from source zones: отметьте vpn.
  5. Save & Apply.
Если у устройства другой шлюзКогда шлюз устройства — не RUT950 (или устройство отвечает только своей подсети), включите Masquerading для трафика из VPN в LAN (зона lan → Masquerading), либо пропишите на устройстве маршрут 10.8.0.0/24 через 192.168.50.1.

8Подключение вашего компьютера

  1. На сервере создайте клиента: 
    sudo ./openvpn-rut.sh add-client laptop
  2. Скачайте конфиг на компьютер: 
    scp root@203.0.113.10:/root/openvpn-clients/laptop/laptop.ovpn .
  3. Установите OpenVPN Connect (openvpn.net/client) или OpenVPN GUI (Windows).
  4. Импортируйте laptop.ovpn (Import Profile → File) и подключитесь.

Для телефона создайте отдельного клиента (add-client phone) и импортируйте его .ovpn в приложение OpenVPN Connect (Android / iOS). Не используйте один сертификат на нескольких устройствах одновременно.

9Проверка доступа к устройству

С подключённого к VPN компьютера:

ping 10.8.0.1          # сервер
ping 10.8.0.2          # роутер в VPN (адрес см. в команде list)
ping 192.168.50.1      # роутер в его LAN
ping 192.168.50.100    # устройство

Дальше используйте устройство как в локальной сети: веб-интерфейс (http://192.168.50.100), RDP, SSH, Modbus TCP, камеры и т.д. Веб-интерфейс самого роутера: https://192.168.50.1.

Проверить маршрут в Windows: route print 192.168.50.* — должна быть строка с шлюзом 10.8.0.1.

ГотовоЕсли устройство отвечает — настройка завершена. Роутер будет автоматически переподключаться к серверу после перезагрузки или смены сети.

Управление

Команда (на сервере)Действие
sudo ./openvpn-rut.sh listСписок клиентов и роутеров, кто сейчас online и с каким VPN-адресом
sudo ./openvpn-rut.sh add-client <имя>Новый пользователь (ПК, телефон)
sudo ./openvpn-rut.sh add-router <имя> <подсеть>Ещё один роутер (у каждого — своя уникальная LAN-подсеть)
sudo ./openvpn-rut.sh revoke <имя>Отозвать доступ (сертификат попадает в CRL)
sudo ./openvpn-rut.sh uninstallПолностью удалить сервер

Несколько роутеров: например add-router obj1 192.168.51.0/24, add-router obj2 192.168.52.0/24. Подсети не должны совпадать. Ваш компьютер получит маршруты ко всем объектам сразу (переподключите VPN-клиент после добавления роутера).

Два и более OpenVPN-подключения на RUT950

RutOS позволяет создать на одном роутере несколько OpenVPN-конфигураций одновременно: несколько клиентов, или клиент + сервер. Каждая получает свой интерфейс (tun_c_vps, tun_c_vps2…). Типичные сценарии:

СценарийКак сделать
Два разных сервера (например, свой VPS и сервер заказчика)На каждом сервере — свой add-router. На RUT950 — две конфигурации Client (vps1, vps2) с файлами от соответствующих серверов.
Основной + резервный серверДве конфигурации Client к двум VPS; LAN-подсеть роутера указывается на обоих. Либо одна конфигурация с двумя строками remote в .ovpn — переключение произойдёт автоматически.
Клиент к VPS + собственный сервер на роутереВозможно, если у SIM-карты белый IP. Вторая конфигурация с ролью Server.
Ограничения
  • VPN-подсети разных серверов не должны совпадать (например 10.8.0.0/24 и 10.9.0.0/24 — на втором сервере используйте install --vpn-net 10.9.0.0).
  • Не подключайтесь дважды к одному серверу с одним сертификатом — сервер будет разрывать одну из сессий. Для второго подключения к тому же серверу нужен отдельный сертификат.
  • Если конфигурации-серверы используют один порт — назначьте им разные порты.
  • У RUT950 слабый процессор: шифрование ограничивает скорость примерно до 5–15 Мбит/с суммарно на все туннели. Для телеметрии и веб-интерфейсов этого достаточно.
  • В firewall разрешите VPN → LAN для каждой новой зоны/интерфейса (шаг 7).

Диагностика и частые проблемы

Где смотреть логи

# сервер
systemctl status openvpn-server@server
journalctl -u openvpn-server@server -f
cat /var/log/openvpn-status.log

# роутер: System → Administration → Troubleshoot → System log, или по SSH:
logread | grep -i openvpn
СимптомПричина и решение
TLS key negotiation failed to occur within 60 secondsПакеты не доходят до сервера: закрыт порт в облачном firewall хостера; не совпадает протокол/порт; оператор блокирует UDP — переустановите сервер с --proto tcp --port 443.
TLS Error: cannot locate HMAC in incoming packetНе загружен ta.key или HMAC key direction ≠ 1.
certificate verify failedЗагружен чужой ca.crt или сертификат отозван. Скачайте файлы заново.
Ошибки шифра / cipher not supportedВыберите на роутере Encryption = AES-256-CBC; обновите прошивку.
Роутер Connected, но LAN недоступнаFirewall роутера (шаг 7); одинаковые подсети у вас и у роутера (шаг 3.2); VPN-клиент на ПК подключён до добавления роутера — переподключитесь.
Роутер пингуется, устройство — нетFirewall на самом устройстве (Windows блокирует ping из «чужих» подсетей); у устройства другой шлюз — включите Masquerading.
Соединение периодически рвётсяНормально для мобильной сети — клиент переподключается сам. Проверьте уровень сигнала (Status → Mobile).
«Серый» IP на SIM-картеНе проблема: роутер сам инициирует подключение к серверу.

Безопасность

  • Файлы *.key и *.ovpn — это пароли. Не пересылайте их открыто, не публикуйте и не храните в репозитории.
  • Каждому устройству и человеку — свой сертификат. При потере устройства или увольнении сотрудника — сразу revoke.
  • После настройки удалите архивы с компьютера или храните в зашифрованном виде.
  • На VPS отключите вход root по паролю (используйте SSH-ключи), регулярно делайте apt upgrade.
  • Смените стандартный пароль веб-интерфейса RUT950 и при необходимости ограничьте доступ к нему из WAN.
  • Сделайте резервную копию /etc/openvpn/ — без неё при переустановке сервера придётся заново настраивать все роутеры.
