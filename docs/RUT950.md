# Настройка Teltonika RUT950 как OpenVPN-клиента

Инструкция для RutOS (RUT950). Названия пунктов меню немного отличаются
в разных версиях прошивки — ориентируйтесь на смысл полей.

## 0. Подготовка

1. **Обновите прошивку** роутера до последней (System → Firmware).
2. **Смените LAN-подсеть роутера**, если она `192.168.1.0/24` (по умолчанию).
   Эта же подсеть почти наверняка у вас дома/в офисе, и маршрут через VPN
   работать не будет. Network → LAN → IP address, например `192.168.50.1`,
   маска `255.255.255.0`. Именно эту подсеть (`192.168.50.0/24`) передайте
   в `add-router` на сервере.
3. Убедитесь, что у устройства за роутером **шлюз по умолчанию = IP роутера**
   (`192.168.50.1`). Если это не так — см. п. 4 «Маскарадинг».

## 1. Скачайте файлы с сервера

На сервере после `add-router rut950 192.168.50.0/24` создаётся папка
`/root/openvpn-clients/rut950/`:

| Файл          | Назначение                         |
|---------------|------------------------------------|
| `ca.crt`      | Сертификат центра сертификации     |
| `rut950.crt`  | Сертификат клиента (роутера)       |
| `rut950.key`  | Закрытый ключ клиента              |
| `ta.key`      | Ключ TLS-auth (HMAC)               |
| `rut950.ovpn` | Всё в одном файле                  |

Скачать на ПК:

```powershell
scp root@SERVER_IP:/root/openvpn-clients/rut950.tar.gz .
tar -xzf rut950.tar.gz
```

## 2. Создайте OpenVPN-клиент на роутере

**Services → VPN → OpenVPN** → в поле «Create new configuration» введите имя
(например `vps`), роль **Client** → **Add** → **Edit**.

### Вариант А — загрузка .ovpn (новые прошивки RutOS 7.x)

Если есть переключатель **Enable external services / Upload OpenVPN config file**,
загрузите `rut950.ovpn` — все параметры подставятся автоматически.
Включите **Enable** и сохраните.

### Вариант Б — ручная настройка

| Поле                                   | Значение                              |
|----------------------------------------|---------------------------------------|
| Enable                                 | ✔                                     |
| TUN/TAP                                | TUN (tunnel)                          |
| Protocol                               | UDP (или как задали `--proto`)        |
| Port                                   | 1194 (или `--port`)                   |
| LZO / Compression                      | None / No                             |
| Encryption                             | AES-256-CBC (на новых прошивках можно AES-256-GCM) |
| Authentication                         | TLS                                   |
| TLS cipher                             | All                                   |
| Remote host/IP address                 | внешний IP или домен сервера          |
| Resolve retry                          | infinite                              |
| Keep alive                             | `10 60`                               |
| Remote network IP / netmask            | оставить пустым (не требуется)        |
| HMAC authentication algorithm          | SHA256                                |
| Additional HMAC authentication         | **tls-auth** (Authentication only)    |
| HMAC authentication key                | `ta.key`                              |
| HMAC key direction                     | **1**                                 |
| Certificate authority                  | `ca.crt`                              |
| Client certificate                     | `rut950.crt`                          |
| Client key                             | `rut950.key`                          |

Если в форме есть поле **Extra options** — можно добавить `remote-cert-tls server`.

Нажмите **Save & Apply**.

## 3. Проверка подключения

* В списке OpenVPN статус должен стать **Connected**.
* Status → Network → (или Status → Routes) — появится интерфейс `tun_c_vps`
  с адресом `10.8.0.x`.
* На сервере: `sudo ./openvpn-rut.sh list` — роутер будет `online`.
* Логи роутера: System → Administration → Troubleshoot → System log,
  или по SSH: `logread | grep -i openvpn`.

## 4. Firewall на роутере

RutOS обычно автоматически помещает OpenVPN-интерфейс в зону **vpn/openvpn**.
Проверьте **Network → Firewall → General Settings → Zones**:

* у зоны `vpn` (`openvpn`): Input = **Accept**, Output = **Accept**, Forward = **Accept**;
* в **Allow forward to destination zones** для зоны `vpn` отмечена **lan**;
* в **Allow forward from source zones** для зоны `lan` отмечена **vpn** (для ответов).

**Маскарадинг.** Если у устройства за роутером другой шлюз по умолчанию
(или устройство не принимает пакеты из чужих подсетей), включите
**Masquerading** на зоне `lan` для трафика из VPN, либо добавьте на
устройстве маршрут `10.8.0.0/24 → 192.168.50.1`.

## 5. Доступ к устройству

1. На сервере создайте клиента для себя: `sudo ./openvpn-rut.sh add-client laptop`.
2. Импортируйте `laptop.ovpn` в OpenVPN Connect / OpenVPN GUI и подключитесь.
3. Обращайтесь к устройству по его локальному IP:

```powershell
ping 192.168.50.100
```

Веб-интерфейс самого роутера тоже доступен: `https://192.168.50.1`.

## Частые проблемы

| Симптом | Причина / решение |
|---------|-------------------|
| `TLS key negotiation failed` | Не открыт порт на VPS/в облачном firewall провайдера; неверный протокол/порт; перепутан `ta.key` или key direction ≠ 1 |
| `cipher ... not supported` / `AUTH_FAILED` при согласовании шифра | Выберите на роутере AES-256-CBC |
| Роутер Connected, но устройство не пингуется | Firewall на роутере (п. 4); шлюз устройства; одинаковая подсеть у вас и у роутера (п. 0.2) |
| Пингуется роутер, но не устройство | Firewall на самом устройстве (Windows блокирует ping из «чужих» подсетей) |
| SIM-карта с «серым» IP | Не мешает — роутер сам подключается к серверу как клиент |
